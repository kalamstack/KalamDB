**Goal:** Finish remaining 0.7 work: live ordinal row values, scalar indexes, functions V1.

**Status owner:** [2026-09-01-kalamdb-0.7.md](2026-09-01-kalamdb-0.7.md) (checkboxes, keys, upgrade policy).  
**Design depth:** serialization §18, [indexes](2026-08-30-scalar-secondary-indexes.md), [functions §9](functions-v1-implementation.md).

**Locked (do not reopen):**

- RocksDB **keys** stay today’s storekey / `SeqId` bytes. `kalamdb-serialization` owns **values** only.
- Breaking on-disk format: no hot-path dual-decode; wipe dev data; offline upgrade tool is follow-on.
- Do not create `kalamdb-functions` until Task 5 (Wave 3).
- HTTP / WS / PGWire / SDK payloads stay out of `KOBJ`.

Implement in wave order. Stop at each wave gate. After a wave, tick the matching boxes in the 0.7 tracker.

```text
Wave 2 serde (live ordinal rows)
    ├─► Wave 2 indexes (catalog + hot seek)

            ▼

            │
            ▼
```

## Wave 2 — Catalog and hot path

### S1. Trim identity from the ordinal row codec

**Files:** [`row/encode.rs`](../../backend/crates/kalamdb-serialization/src/row/encode.rs), [`row/decode.rs`](../../backend/crates/kalamdb-serialization/src/row/decode.rs), [`row/metadata.rs`](../../backend/crates/kalamdb-serialization/src/row/metadata.rs), tests next to the crate.

**Change:** Stop writing `user_id` and `_seq` into the payload. Target body:

```text
schema_version u16
commit_seq     u64 LE
deleted        u8
field_count    u16
ordinal values[]
```

Decode APIs take key identity + schema + bytes:

- `decode_user_row(bytes, schema, user_id, seq) -> UserTableRow`
- `decode_shared_row(bytes, schema, seq) -> (commit_seq, deleted, Row)`
- STREAM: same envelope with `commit_seq = 0`, `deleted = 0` (stream rows have neither field today). Reconstruct `user_id`/`_seq` from `StreamTableRowId`.

`decode_row_metadata` reads only `commit_seq`/`deleted` (no identity). Extra stored ordinals (dropped columns) are skipped; missing trailing slots become NULL.

**Tests:** round-trip user/shared/stream; nested STRUCT/List; additive field → NULL; payload must not contain the user_id string.

**Verify:** `cargo nextest run -p kalamdb-serialization`

### S2. `StorageSchema` from `TableDefinition`

**Files:** new helper in `kalamdb-serialization` (e.g. `row/from_table.rs`) or a small function in tables that the store owns. Prefer the serialization crate so catalog/functions reuse it. Map [`KalamDataType`](../../backend/crates/kalamdb-commons/src/models/datatypes/) → [`StorageDataType`](../../backend/crates/kalamdb-serialization/src/row/schema.rs).

**Rules:**

- Physical slot order = `column_id` ascending (stable, never reused). **Not** `ordinal_position` (SELECT * order).
- `schema.version` = `TableDefinition.schema_version` (u32 → u16; fail if it does not fit).
- Nested `CREATE TYPE` / STRUCT / List recurse using the same mapping.
- System columns `user_id` / `_seq` are **not** schema slots (they live on the key). `_commit_seq` / `_deleted` are envelope fields, not ordinals.

**Tests:** two columns with ids 1 and 3 after a drop; rename does not change slot; nested type maps to `StorageDataType::Struct`.

**Verify:** `cargo nextest run -p kalamdb-serialization -p kalamdb-commons`

### S4. Live USER/SHARED/STREAM write and read path

**Files:**

- [`persist.rs`](../../backend/crates/kalamdb-store/src/persist.rs) — row stores must not call `V::encode()`. Either schema-aware encode at the table layer, or pass schema into the store. Preferred: providers/stores encode with `ObjectEncoder` / `encode_user_row` and keep using `insert_batch_preencoded`; `EntityStore::insert` for rows must take the same path (do not go through `USES_ROW_CODEC`).
- [`entity_store.rs`](../../backend/crates/kalamdb-store/src/entity_store.rs), [`indexed_store.rs`](../../backend/crates/kalamdb-store/src/indexed_store.rs)
- [`user_table_provider.rs`](../../backend/crates/kalamdb-tables/src/user_tables/user_table_provider.rs) (~252, ~437): replace `batch_encode_user_table_rows`
- [`shared_table_provider.rs`](../../backend/crates/kalamdb-tables/src/shared_tables/shared_table_provider.rs) (~1890): replace `batch_encode_shared_table_rows`
- [`user_table_store.rs`](../../backend/crates/kalamdb-tables/src/user_tables/user_table_store.rs), [`shared_table_store.rs`](../../backend/crates/kalamdb-tables/src/shared_tables/shared_table_store.rs), [`stream_table_store.rs`](../../backend/crates/kalamdb-tables/src/stream_tables/stream_table_store.rs)
- [`ObjectEncoder`](../../backend/crates/kalamdb-serialization/src/lib.rs) — implement `encode_user_row` / `encode_shared_row` (and stream) with reused buffers
- Remove `USES_ROW_CODEC` from `UserTableRow`, `SharedTableRow`, `SystemTableRow`, `Row`. System rows use `encode_object`, not the row profile.

**Decode:** after `get`, parse key (`UserTableRowId::from_storage_key` / `SeqId::from_bytes`) then `decode_*_row(..., schema)`. Stores need a `StorageSchema` (from cached `TableDefinition`).

**Acceptance:** new inserts are KOBJ ordinal; no commons `row_codec` on the write/read path; identity rebuilt from key.

**Verify:** `cargo nextest run -p kalamdb-serialization -p kalamdb-store -p kalamdb-tables`
